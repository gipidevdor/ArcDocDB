# ADR-0014 — Record, document, and `_id` format

> **Revision:** [ADR-0048](0048-limiti-documentali-e-formato-v2.md) supersedes the relevant document limits and v2 layout. The text below preserves the historical v1 decision.

- **Status:** Accepted; **partially superseded by [ADR-0039](0039-cornice-unica-dei-record.md)**: 24-byte header with two CRCs, PUT, TOMBSTONE, SEAL, OUTCOME types (item 3). Document, `_id`, and hash remain.
- **Date:** 2026-10-03
- **Relationship to the specification:** closes QA-01
- **References:** [on-disk formats](../formati-su-disco.md#cornice-del-record), INV-F1

<a id="contesto"></a>

## Context

The record is the unit written to segments; it must support sequential reading without an index
(recovery, CLEAN, scans), be verifiable, and be compact for the in-memory index.

<a id="decisione"></a>

## Decision

1. **Document.** Storage treats the document as **opaque bytes**. The canonical encoding
   for the Query Engine and protocol is **CBOR (RFC 8949)** with deterministic encoding: binary,
   standard, self-describing, implementable in a few hundred lines of Common Lisp, with
   integers, strings, bytes, arrays, maps, dates, and tags for extended types.
2. **`_id`.** A byte sequence of length 1–255 chosen by the client or generated by the server.
   Comparison is bytewise. A generated `_id` is a time-sortable 16-byte identifier
   (timestamp + random, in ULID style), which favors locality in scans.
3. **Record.** Fixed-length binary header (little-endian), key, value, CRC32C
   (Castagnoli) over the entire record. Types: PUT, TOMBSTONE, PREPARE, COMMIT-GROUP, OUTCOME.
   Details in [on-disk formats](../formati-su-disco.md#cornice-del-record). Maximum record
   size: **16 MiB − 1** (index location limit,
   [ADR-0015](0015-primary-index-swiss-table-swmr.md)); maximum document size
   configurable per Serie, default 4 MiB ([limits](../limiti.md)).
4. **Index.** The index stores a 64-bit key hash and a reference to the key in
   an in-memory **key arena**; key verification takes place in RAM, never by reading the
   record ([ADR-0015](0015-primary-index-swiss-table-swmr.md)).
5. **Hash.** Noncryptographic 64-bit function with a per-Serie seed (xxHash/wyhash style),
   implemented in typed Common Lisp.

Patterns: length-prefixed records with CRC32C (RocksDB, Kafka); CBOR as document encoding
(IETF standard); ULID for sortable identifiers.

<a id="conseguenze"></a>

## Consequences

- Every persistent file can be scanned and verified independently.
- No library dependencies: CBOR, CRC32C, and hashing are project code (table-driven,
  typed, allocation-free).
- The 255-byte `_id` limit keeps the header compact; long keys are not a use
  case.

<a id="alternative-considerate"></a>

## Alternatives considered

- *Text JSON:* expensive parsing, ambiguous numbers, no binary type.
- *Proprietary binary format:* no advantage over CBOR and no standard.
- *Only fixed 16-byte `_id`:* more compact, but prevents natural keys.

<a id="valutazione"></a>

## Assessment

- Verification: CBOR round-trip tests against RFC vectors; FI-01 (truncated record).
- Cost: ~44 bytes of header+CRC per record, negligible for 1–4 KB documents.
