# ADR-0022 — Registri is a Serie; the catalog consists of documents

- **Status:** Accepted; **partially superseded by [ADR-0040](0040-manifest-a-record-unico.md)** §5: creation with a `.tmp` directory and a document as the decision, `active` and `dropping` states (item 3). The rest remains.
- **Date:** 2026-10-03
- **Relationship to the specification:** closes QA-10; implements "Special Serie Registri," "Catalog"
- **References:** [architecture](../architettura.md#archivio-e-registri), RSK-15

<a id="decisione"></a>

## Decision

1. **Registri is a full-fledged Serie**, with storage in `Registri/catalog/`
   (containing `wal/`, `segments/`, `index/`) and configuration **embedded in the code**
   (durability `:strong`, 16 MB target segment size, secondary index on name). Users cannot
   modify or delete it.
2. **Each Serie is a document** in Registri, with `_id` = stable internal identifier
   (16 generated bytes) and a CBOR body: name, state, configuration, contract, indexes,
   segment configuration, recovery metadata. The Serie directory is
   `<Archivio>/<id-esadecimale>/`; the logical name lives only in the catalog (rename = one
   write).
3. **Serie creation** (single-Serie transaction on Registri): create the directory
   with the initial files and synchronize it; then write the document with state `creating`;
   open the Serie; update the document to `active`. On restart, a directory without a
   document or with state `creating` is removed; `dropping` is completed.
4. **Bootstrap:** recovery opens Registri first (configuration known in advance), reads
   the catalog, then opens the other Serie in parallel.
5. `multiserie.log` lives in `Registri/` next to `catalog/` and is managed by the Archivio
   coordinator, not by the Registri writer.
6. The name `Registri` is reserved.

Pattern: system catalog stored in the engine itself (PostgreSQL `pg_catalog`).

<a id="conseguenze"></a>

## Consequences

- A single durability mechanism for data and catalog; the catalog inherits transactions,
  recovery, and fault injection.
- The constant Registri configuration resolves the circularity.
- DDL operations follow an explicit state machine (`creating`, `active`,
  `dropping`) that can be repeated after a crash.

<a id="alternative-considerate"></a>

## Alternatives considered

- *Atomically rewritten catalog file:* a second mechanism to verify, with no
  advantage.

<a id="valutazione"></a>

## Assessment

- Verification: fault injection on Serie creation/deletion (scenario to add to the
  FI catalog as FI-13).
