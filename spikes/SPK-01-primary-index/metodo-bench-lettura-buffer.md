## Hypothesis and fixed matrix

Compare baseline `ARCDOCDB.SPK01:LEGGI`, returning four fields, status, retry,
with `ARCDOCDB.SPK01.LETTURA-BUFFER:LEGGI`, returning status/retry and publishing
four u64s into a private buffer after seqlock/root validation.
One immutable index instance per cell serves both methods. No writer during
warmup/measurement. Barriers, root recheck, and writer behavior remain existing-module
responsibilities; the benchmark does not reimplement them.

<a id="dati-e-consumatore-comune"></a>

## Data and shared consumer

Defaults: 4096 documents, C=8192, 128000 actual lookups per sample
(here 128k means 128000), 4096 warmup lookups per method/cell.
Outside measurement, prepare unique 16-byte document/new-miss keys, two query
arrays of length 2*documents, four independent fields per document/cell,
preallocated u64 oracles/status bytes per cell. Hit-only traverses two population
permutations; mixed alternates hit/miss (50% per full period), starting with hit.
A miss uses an ID distinct from every document. Deterministic order with multiplier
104729, no RNG or key generation in the loop.

Tuples are generated before insertion; the oracle is built from tuples, never by reading
the index. CSN, location, length, end-CSN use separate formulas. Extreme profile's
CSN/location/end include 2^64-1 and nearby values; length includes v1 limit
2^24-1. words4 always has zero end-CSN. The location is split into u32 segment/offset
only for insertion. Neither the core's correlated pattern nor the v2 layout is used.

Two compiled loops generated by a common macro call the typed APIs directly:
there is no lookup FUNCALL. The consumer/oracle check uses the same expansion in both loops.
On a hit, compare exactly four u64s. On a miss, the baseline retains four previous-hit
values; the variant reads the buffer that must retain that payload. The miss oracle is
the previous-hit payload. The baseline is not copied into the buffer to simulate the other API.
The four baseline-returned values on a miss are ignored: they are not valid payload.
Retry-limit, unexpected state, retry in this immutable fixture, different field,
or insufficient operation count are errors.

The checksum remains a nonnegative 60-bit fixnum: for each u64, combine low 60 bits and
high 4 bits after rotating the checksum. No u64 sink extraction for printing in the loop.
Checksum does not replace full four-field comparison. Status/retry are included;
both methods must have equal checksum, hit, miss, retry per pair.
No hash-table, explicit cons, report, list, key generation, or oracle construction
in the loop. API allocations, including baseline boxing, are exactly what is measured.

<a id="finestra-gc-e-contatore-positivo"></a>

## Window, GC, and positive counter

Preparation, buffer initialization, warmup, full GC, and reports are outside the window.
Full GC precedes each sample. The window includes lookup, query/oracle access,
verification, checksum, counts, cooperative guards every 256 operations.
GC triggered within the loop is included. Wall ticks from GET-INTERNAL-REAL-TIME,
exact ns/op derived from ticks/timer units, GET-BYTES-CONSED delta;
zero ticks or negative delta are errors. The consed counter is process-wide:
no other benchmark/worker may run concurrently. The destination is a private exact-length-4
u64 simple-array per cell/caller; module creates no threads.

Before preparation/measurement, run positive counter control outside measurement:
full GC, before, allocate 262144-byte u8 vector published in module global, after.
The global remains live at least until the delta is computed. Only after the second counter
reading, read its contents and obtain SB-EXT:PRIMITIVE-OBJECT-SIZE for the actual object. Report before, after, delta,
elements, payload, read value, actual size. Nonpositive/below-payload delta is an error.
No inference about heap payload of nonescaped arrays. Actual size is an out-of-window
diagnostic; payload ceiling excludes headers, heap ceiling includes runtime-observed
dynamic usage.

## API and budgets

Package `ARCDOCDB.SPK01.BENCH-LETTURA-BUFFER`, sole export `BENCH`.

| Keyword | Default | Constraint |
| --- | ---: | --- |
| documents | 4096 | 1..max-documents; <=7*C/8 |
| capacity | 8192 | power of two, 8..32768 |
| operations | 128000 | 1..max-operations |
| replicas | 5 | exactly 5 |
| warmup | 4096 | 1..min(max-warmup,operations) |
| time-limit-seconds | 120 | positive real <=max-time-limit-seconds |
| memory-mib | 256 | dynamic heap, 1..1024 MiB |
| attempts | 8 | 1..8 |
| max-documents | 16384 | 1..28672 |
| max-operations | 1000000 | 1..10000000 |
| max-warmup | 65536 | 1..1000000 |
| max-payload-bytes | 33554432 | 1..268435456 |
| max-copy-bytes | 16777216 | 1..67108864 |
| max-consed-bytes | 1073741824 | 1..4294967296 |
| max-time-limit-seconds | 300 | positive real <=300 |

All parameters, split-free load, payload/copy estimates are validated **before any sample**.
Conservative preflight payload: eight v1 fragments/directories, shared keys/queries,
eight oracle/status/buffers, temporary tuple table, positive-control vector.
Counted copies are inserted keys (8*documents*16) and oracle fields
(8*2*documents*32). No maintenance allowed; core counters must remain zero for
splits/rebuilds/maintenance copies.

One cooperative deadline applies to the whole BENCH, default <=120 s, hard cap 300 s,
checked during preparation, between GCs, warmups, samples, reporting, each lookup
block. Heap ceiling through SB-KERNEL:DYNAMIC-USAGE and whole-BENCH cumulative
consed bytes are checked at the same guards. Cumulative consed includes preparation, positive
control, warmup, and reporting; sample delta covers declared window only.
GC/allocations/calls are not asynchronously interrupted: cooperative overshoot may
be observed, but expiration signals an error. No exhausted budget returns :ok.

BENCH returns plain readable data: lists of keywords/strings/numbers;
types/function names as strings, no spike-package symbols, arrays, pathnames,
or structures in the result. :ok is built only after 80 complete samples, 40 paired
comparisons, final guard. The parent also records errors in a schema 1 envelope,
without promoting sample prefixes to complete results.
